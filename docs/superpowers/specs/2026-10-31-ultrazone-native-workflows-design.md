# Ultrazone 原生工作流与多模型能力设计

状态：各设计段落已在对话中确认，待用户审阅本文档。

## 给用户看的说明

这部分是全文摘要。审阅时只需先看这里，后面的技术细节供实现使用，不要求用户理解。

Ultrazone 会有三种启动方式：

- `ultrazone`：修改文件、执行命令和重要选择前会问用户。
- `ultrazone --dangerously-skip-permissions`：修改文件和执行命令不再逐个询问，但方案是否开始执行、是否恢复文件等重要选择仍由用户决定。
- `ultrazone --max`：全部自动决定并继续执行，启动页会持续显示明显提醒。

准备增加的能力依次是：

1. 先给方案，用户同意后再修改。
2. 在终端里直接查看哪些文件被改了、改了什么。
3. 查看本次对话占用了多少模型可阅读的空间，以及哪些内容最占空间。
4. 定时执行检查，以及在不打断当前工作的情况下临时提问。
5. 内置代码审查、安全审查、功能开发和提示词检查四组指令。
6. 以上全部完成后，再增加按历史节点恢复对话和文件的能力。

Kimi、DeepSeek 等模型使用同一套任务规则，并通过实际结果检查是否理解正确，不为每个模型单独写一套文案。

### 与用户沟通和请求确认的规则

后续所有方案、问题、风险提示和确认界面都遵守以下规则：

- 默认用户不是技术人员，优先使用日常中文。不得不使用专业词时，先用一句简短的话解释，例如“快照（修改前保存的一份文件副本）”。
- 先说明要做什么、为什么需要、会影响什么，再给出建议。不让用户从内部实现名称猜测后果。
- 不让用户选择“核心还是扩展”“架构还是插件”等内部实现方式。技术路线由助手负责判断，只有会影响费用、数据、权限、操作结果或使用习惯时才请用户选择。
- 只问真正需要用户决定的问题；能从代码、现有文档或既往确认中得到答案时，不再询问。
- 需要选择时，把推荐项放在最前面，并用简短语言说明每个选项的好处、代价和风险。
- 同一件事一次说清楚，不因前面使用了难懂术语而反复追问。已经确认的决定不再重复确认。
- 尽量用具体操作或结果举例，例如“先查看代码并给出方案，你点头后才修改文件”，而不是只写“启用计划工作流”。
- 风险说明必须说清实际后果，例如“可能覆盖你刚刚手动修改的内容”，而不是只展示内部错误名称。
- 文件名、代码位置和技术标识可以放在实现说明或附录中，但不作为用户做决策的主要阅读内容。

这条规则只约束人与用户之间的沟通，不改变供模型读取的内置提示词使用简短英文的设计。

## 三档执行模式

### 模式定义

| 启动方式 | 内部模式 | 工具与命令审批 | 关键流程 | 项目信任 |
| --- | --- | --- | --- | --- |
| `ultrazone` | `default` | 只读自动；写入、Shell、未知副作用工具需审批 | 用户确认 | 用户确认 |
| `ultrazone --dangerously-skip-permissions` | `auto` | 全部自动执行 | 用户确认 | 用户确认 |
| `ultrazone --max` | `max` | 全部自动执行 | 自动决策并继续 | 仅本次进程自动允许 |

关键流程至少包括计划批准、文件回滚、项目资源信任，以及会改变后续执行方向的流程选择。

### 通用规则

- 两个标志由核心参数解析器处理，同时传入时直接报错。
- 模式只对当前进程有效，不写入用户设置。
- 恢复一个曾经运行于 MAX 的会话时，如果没有再次传入 `--max`，仍按当前启动模式执行。
- 历史会区分用户批准和 MAX 自动批准。
- 登录、API Key、缺失参数等信息收集不属于审批，必要时仍可询问。
- 非交互模式不能弹出问题时：默认模式拒绝需要审批的工具或流程；AUTO 可执行普通工具，但遇到计划、回滚或信任等关键流程时停止并说明需要交互确认；MAX 自动决策。所有结果记录原因。
- 所有工作流和定时任务继承当前进程模式，不因后台执行提升权限。

### 不可绕过的条件

以下不是审批，任何模式都不能用自动决策替代：

- 工具参数和协议有效性检查。
- 操作系统权限和远程服务拒绝。
- 文件外部修改冲突、符号链接与硬链接保护。
- 快照缺失或无法证明可安全恢复。
- 防重入、失败停止和资源上限。

## F1：`/plan` 计划模式

### 状态与流程

- `/plan [目标]` 在空闲时进入计划模式；Agent 执行中拒绝切换。
- 计划目标、草稿、状态和批准记录保存在会话树的专用条目中。
- 计划状态随会话分支隔离，恢复会话可还原，但执行权限仍由当前进程模式决定。
- `/new` 清空当前计划状态；`/tree`、`/fork` 和 `/clone` 不共享可变的全局计划文件。
- 裸 `/plan` 查看当前计划。
- 用户可选择批准执行、继续规划或取消计划。
- 模型不能自行批准或退出计划模式。
- 默认和 AUTO 模式等待用户批准；MAX 自动批准最新计划，在界面和会话中留下记录后继续。

### 工具约束

约束位于执行层，不依赖模型遵守文字：

- 允许 `read/grep/find/ls` 等内置只读工具。
- 允许明确标记 `readOnlyHint` 的工具。
- 未证明只读的 MCP 和自定义工具默认拒绝。
- 拒绝 `edit/write/codemode` 及其他有副作用的工具。
- Shell 仅允许无管道、无重定向、无命令替换、无环境赋值的简单只读命令。
- 首批只读命令包括限定参数的 `git status/diff/log/show`、`rg`、`fd` 等；解析不确定时拒绝。
- 嵌套工具调用使用同一判定，防止通过其他工具绕过。

### 验收

- 直接和嵌套写入均被拦截。
- 未知 MCP 工具和 Shell 绕过样本失败关闭。
- 批准、取消、继续规划、恢复和分支行为正确。
- AUTO 仍询问，MAX 自动批准且历史可辨。

## F2：`/diff` 变更视图

### 数据来源

- 支持会话开始时的 HEAD、当前 HEAD、默认分支 merge-base 三种基准。
- “会话变更”表示相对于会话开始时的状态，不宣称只包含 Agent 修改。
- 包含未跟踪文件和重命名。
- 锁文件和生成文件默认分组折叠；测试文件始终按普通变更展示。
- 非 Git 目录和无提交仓库提供明确状态，不显示伪造空 diff。

### 界面与刷新

- 使用浮层展示文件列表和 hunks，窄终端改为上下布局。
- 第一版不自动弹出，不增加复杂侧栏。
- 编辑、写入和 Shell 命令完成后防抖刷新。
- 仅在视图打开时轮询 HEAD；慢 Git 或连续超时采用退避。
- Git 调用只读并使用 `--no-optional-locks`，避免占用 index lock。
- 视图关闭后停止后台刷新。

### 验收

使用临时 Git 仓库覆盖干净状态、已有修改、未跟踪文件、重命名、merge-base、非 Git 目录、慢命令、刷新失败和关闭后的清理。

## F6：`/context` 上下文体检

### 展示内容

- 当前模型、上下文窗口、压缩预留量、当前占用和剩余空间。
- 系统提示各段、项目说明、已加载技能、工具定义、用户与助手消息、工具结果和图片的分类组成。
- 占用最高的工具结果与实际进入上下文的资源。
- 未加载或未展开的提示词模板不计入当前上下文。
- 根据确定性规则建议压缩、减少无用技能、避免重复读取或缩小工具输出；不自动执行。

### 多模型计数语义

- 最近一次提供商报告的用量标为“实际报告”。
- 分类组成复用现有 `estimateTokens`，标为“估算”。
- 不把字符估算描述为任何模型的精确 tokenizer。
- 不为 Kimi、DeepSeek 或其他提供商硬编码不同估算公式。

### 验收

覆盖已知长度消息、实际与估算标签、压缩后统计、inactive 资源排除、不同上下文窗口和大型工具结果排序。

## F8a：`/loop` 会话内定时任务

### 命令

- `/loop <interval> <prompt>`
- `/loop list`
- `/loop pause <id>`
- `/loop resume <id>`
- `/loop stop <id>`

### 调度规则

- 仅在当前会话和当前进程中运行。
- 退出、新建或切换会话后停止；重启后不自动恢复执行。
- 只在主会话空闲时触发；忙碌时跳过，不积累补跑。
- 多 Loop 不重叠执行，禁止 Loop 创建 Loop。
- 计划模式期间暂停，退出后恢复。
- 连续失败采用退避，达到上限自动暂停并显示原因。
- 使用 `[loop:id]` 标记执行、跳过、暂停和费用。
- 分支和克隆不复制活动定时器。
- 设置最小间隔，拒绝零、负值和过高频率。

默认和 AUTO 下，用户输入创建命令即表示创建授权；Loop 内的关键流程仍按当前模式处理。MAX 可自动继续，但仍受防重入和失败停止规则约束。

### 验收

使用虚拟时钟覆盖空闲触发、忙碌跳过、无补跑、计划模式暂停、失败退避、停止清理、分支不继承和模式继承。

## F8b：`/btw` 只读旁路提问

### 上下文与执行

- `/btw <question>` 可在主任务运行时提问。
- 使用最后一次完整的主会话上下文快照和当前任务状态。
- 使用当前模型发起独立只读请求，不分配主任务，不启动 subagent。
- 只允许只读工具与只读 Shell，永不继承写入权限。
- 主任务不中断，旁路问题和答案不进入主模型上下文。
- 旁路记录使用独立会话条目保存，裸 `/btw` 可查看历史。
- 同时只允许一个活动旁路请求。
- 文件工具读取实时工作区；主任务修改期间显示“文件可能已变化”。
- 只有用户主动选择“带入主会话”时，答案才进入主上下文。

### 验收

覆盖主任务继续运行、主上下文无污染、只读工具约束、历史恢复、实时文件提示、并发限制和显式带入主会话。

## P 系列提示词

### 统一加载与执行

- 四份提示词作为 Ultrazone 内置 Markdown 资源，通过现有资源加载器注册。
- 构建资源解析使用 `src/config.ts` 的资产辅助函数，不直接使用 `__dirname`。
- 用户和项目模板继续遵循现有覆盖、信任和来源标记规则。
- 增加模板级只读执行元数据；展开时把执行约束传入该次 Agent 运行，结束后恢复。
- P1、P2、P7 的只读约束由核心执行，不仅依赖提示词；MAX 也不能把只读任务变成写入任务。

### P1 `/review`

1. 确认审查范围和实际 diff，默认审查当前变更。
2. 只报告有代码证据的问题。
3. 每项包含严重度、`文件:行号`、触发条件和修复建议。
4. 不报纯风格问题，不用猜测凑数量。
5. 最后列出未运行的测试和残余风险。
6. 没有变更或可靠发现时直接说明。

### P2 `/security-review`

- 默认只读审查当前 diff。
- 关注注入、路径遍历、鉴权、SSRF、XSS、反序列化、密钥和危险文件操作。
- 每项发现包含利用前提、影响路径和代码证据。
- 证据不足时标为待验证，不断言为漏洞。
- 发现密钥只指出位置和类型，不复述密钥内容。

### P3 `/feature`

1. 阅读相关代码和项目规范。
2. 用“问题、简短流程、最小方案”说明。
3. 等待方案确认。
4. 实现并运行覆盖变更的测试。
5. 检查最终 diff，汇报验证和未解决事项。

默认和 AUTO 在第 3 步等待用户；MAX 自动批准。任何模式都不展开 subagent，不做无关重构。

### P7 `/prompt-audit`

- 检查 `AGENTS.md`、技能和提示词模板。
- 找出冲突、重复、无效约束、不必要的绝对化语言、旧模型或厂商假设、不可用工具依赖、隐藏思维过程要求、僵硬格式和不必要的 Token 消耗。
- 输出具体位置、原因和简化建议。
- 默认只读，不自动重写。

## 多模型提示词契约

### 文案规则

- 使用短句、直接、步骤明确的英文指令，回复跟随用户语言。
- 不写 Claude、Kimi、DeepSeek 等模型名称，不维护厂商分支。
- 不要求展示隐藏思维过程，只要求证据、必要解释和结论。
- 使用稳定的小标题和列表，不采用容易偏差的复杂 JSON 输出。
- 只使用当前实际可用工具；缺失时说明限制，不虚构工具调用。
- 约束按“任务目标、安全边界、证据、输出形式、风格”排序，缩减文案时保留高优先级内容。

### 测试与真实模型验收

- 模板解析、参数展开和只读元数据使用确定性单元测试。
- 工具约束、计划批准和工作流使用 `test/suite/harness.ts` 与 faux provider。
- 真实模型矩阵复用同一 fixtures，评估任务完成度、工具合法性、证据准确性、越权行为和 subagent 禁用，不比较固定措辞。
- Kimi、DeepSeek 真实 API 验收必须由用户另行明确授权，不纳入默认测试自动触发。
- 某模型失败时优先简化通用契约或修复工具兼容性，不立即增加厂商专属提示词。

## F5：`/rewind` 文件检查点与回滚

F5 严格在上述功能完成并通过验收后启动。

### 快照范围

- 在核心 `edit/write` 实际修改前，于现有文件修改队列内获取快照，避免读写竞态。
- 检查点关联会话条目、用户轮次、文件前后哈希和文件原本是否存在。
- 支持文本与二进制，保留可跨平台保留的权限信息。
- 使用内容寻址去重，快照位于 Ultrazone 私有配置目录，不进入模型上下文。
- 超限文件明确标记未快照。

第一版不保证 Shell、未知自定义工具、远程文件系统、符号链接或硬链接目标的完整恢复。可以回滚对话时必须明确标出文件恢复不完整。

### 用户流程

- 按用户轮次列出检查点、消息摘要、文件数和不可恢复项。
- 支持只回滚对话，或同时回滚对话与已捕获文件。
- 对话使用现有会话树分支，原始分支不删除。
- 恢复前展示待恢复、待删除、冲突和无法恢复的文件。
- 不使用 `git reset --hard`，不覆盖整个工作区。

### 安全恢复

1. 对全部目标文件预检。
2. 比较当前内容与最后 Agent 写入后的哈希，识别用户或外部进程后续修改。
3. 默认和 AUTO 可让用户把冲突文件明确排除在本次恢复之外；被排除文件保持原样，最终结果显示“部分恢复”，不得称为完整回滚。
4. 对本次实际恢复的文件备份当前状态并写入事务日志。
5. 逐文件原子替换；新建文件仅在仍符合预期时删除。
6. 实际恢复集合中的任一文件失败时，用备份撤销本次恢复，保持会话位置不变。
7. 实际恢复集合全部成功后才切换会话分支；存在排除项时同步记录部分恢复状态。
8. 启动时发现未完成事务，先恢复一致性并提示。

默认和 AUTO 由用户确认目标、范围和冲突处理。MAX 自动恢复明确目标；未指定时选择最近安全检查点，范围默认为对话及全部可安全恢复的文件。冲突或缺失快照的文件被排除并记录为部分恢复；MAX 仍不能强行覆盖这些文件。

### 保留与复用

- 按总大小和数量限制快照。
- 只清理不再被任何会话分支引用的内容。
- 相同内容跨轮次去重。
- 复用 F2 的 diff 渲染进行恢复预览，但 F2 不依赖 F5。

### 验收

覆盖 CRLF、二进制、新文件恢复、外部修改、符号链接、硬链接、超限文件、备份缺失、中途失败回滚、会话分支、崩溃恢复、保留清理和三档模式。

## 通用验证要求

- 本地依赖安装仅使用 `npm install --ignore-scripts`；缺少依赖的问题先修复，不绕过标准检查。
- 每次代码变更后运行完整输出的 `npm run check`，修复所有 errors、warnings 和 infos。
- 新增或修改的测试必须在对应包中单独运行并通过。
- 非 E2E 测试按项目规定通过 `./test.sh` 或指定 Vitest 文件运行，不直接触发完整 E2E。
- 不运行未经用户明确要求的 `npm run build` 或 `npm test`。
- 真实终端分别验证默认、AUTO、MAX 的启动和关键流程，使用 faux provider，不调用真实付费模型。
- 更新受影响的 CLI、会话、安全、提示词和交互文档，以及描述旧行为的注释。
- 工作结束前检查 `git status`，删除验证过程产生且不需要的临时文件。
- 不执行 commit。

## 已确认的边界与假设

- 本轮不选择 F3 `/goal`、F4 完整权限规则系统和 F7 历史搜索。
- 基本三档执行控制是本轮新增需求，不等于实现完整企业权限体系。
- Loop 不做重启后自动执行，避免未经确认的后台费用。
- Btw 是只读旁路请求，不是主任务分包。
- F5 首版只保证本地核心 `edit/write` 捕获到的文件变化。
- Kimi、Moonshot 和 DeepSeek 提供商已经存在，本轮重点是多模型行为契约，不重复建设提供商。
- 设计文档只提交给用户审阅，不提交 Git；用户审阅通过后再编写分阶段实施计划。
